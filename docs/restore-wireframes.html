R6-A · Today — a timeline of blocks
  • The day is blocks, not one list: each knows its context (home, desk, gym) and only contains what works there.
  • Cycle phase lives in the header with one plain-language note that tunes the day — sourced from config, tailored to you.
  • Times are suggestions from config, not alarms; blocks can run in any order and back-fill freely.
  • Tapping a block opens it: the morning block opens the audio player (next frame), the gym block opens the session (frame C).

R6-B · Hands-free audio player
  • One tap starts the whole block: it announces each exercise, speaks the coaching cue, counts the time, chimes at side-switches and transitions, and auto-advances.
  • Ends with “Done — 12 minutes,” ticks the block itself. You never touch the screen.
  • Voice is the browser/system voice in the wireframe app; the native iOS version gets proper background audio with the screen locked.
  • Skip / repeat / pause for the days a side needs longer.

What I’d like your eye on

This round is about behavior, not looks:

  1. The block set — morning stretch / desk resets / gym / evening check-in. Is that your real day? Anything missing (evening wind-down stretch? walk block on non-gym days)?
  2. The audio player — auto-advance with spoken cues as shown, or would you rather it wait for a tap between exercises?
  3. Gym logging — last-session-beside-today with auto rest timer: right level of detail, or too much tapping mid-workout?
  4. Check-in contents — tension + period + note. Anything else worth 5 more seconds (sleep quality? soreness?), or is three the max?

Behavior locked → I run your program intake in chat, compile the real config, and build v1. The living wireframe stays the design source of truth for the SwiftUI port.
